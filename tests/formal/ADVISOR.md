# Advisor pass verification

Run `bash scripts/check_advisor_specs.sh` on macOS arm64 or Linux x86_64 with Node 26.13.1 and Rust 1.99.1. The `advisor-specs` job in `.github/workflows/ci.yml` runs the same command without provider credentials. The runner installs Quint 0.33.0 from the npm lockfile, checksum-verifies Apalache 0.62.1, Alloy 6.2.0 and Temurin 25.0.5+8, and checks the Alloy CLI help before selecting every named command. Alloy 6.2.0 has no CLI `--expect` option, so the model's explicit `expect 0` and `expect 1` declarations are enforced against the generated receipt. The runner also executes Cucumber 0.23.0 with three negative controls, Rust unit and integration regressions, and checksum-pinned Bats 1.14.0 against freshly built CLI binaries.

Each run records exact invocations in `commands.log` (including the full `quint verify` argv in `quint-verify.log`), numeric exit codes for ordinary checks and expected-failure confirmations for successful Cucumber negative controls in `results.log`, and solver artifacts under `target/formal-reports/advisor.*`. The Cucumber target alone is `cargo +1.99.1 test --locked --all-features --test advisor_bdd`. The randomized simulation uses the TypeScript backend with seed `20261124`, 1,000 samples and up to eight steps. It is not a proof; the separate Apalache check exhausts bounded executions of the abstract model for invariant `safety` through eight transitions. Alloy checks use SAT4J at scope 12.

| Contract | Executable checks |
| --- | --- |
| `apply-advice` requires advice from the immediately preceding successful advisor visit; each step dispatches at most once per pass. | Quint transition invariant and success witness; Cucumber counts dispatched prompts and compares consumed advice to the new session artifact, including `NO FINDINGS`. |
| Disabled, skipped, and failed visits cannot reuse an older artifact. | Quint starts with an optional stale artifact and clears it before review or at skip; Cucumber seeds a stale artifact and tests failure, flag-off, explicit skip, and a remaining consumer that fails for missing advice. |
| Ordinary failure continues without apply; workspace changes, unverifiable guard snapshots, and interrupts stop. | Quint distinguishes terminal classes and checks their transitions; Cucumber injects actual shell failures and mutations into the real workspace guard, including timeout precedence, and asserts no downstream dispatch after a fatal error. |
| An enabled advisor requires jcode before execution; a disabled or user-skipped advisor does not reject the command workflow. | Quint gate; Cucumber computes the skip list and invokes production `validate_workflow` independently of execution. |
| Advisor model precedence is step, advisor, plan, then normal; eligible advisor placements are top-level prompt steps, including inlined ones. | Alloy assertions and satisfiable witnesses; Cucumber checks representative production static diagnostics and observes the selected model in backend arguments, including empty-list fallback and isolation from ordinary steps. |
| Host diff is regenerated before dispatch; missing Git and clean timeouts are ordinary failures; an advisor does not consume `tell` instructions. | Production engine unit tests cover tracked, untracked, ignored and excluded paths, truncation, failure before dispatch, revisit freshness and inbox delivery. |
| The builtin wires one opt-in pass, and CLI entry points respect the gating rules. | Builtin and JSON Schema integration tests; Bats exercises `workflow doctor` and `exec --dry-run` on both backends and checks the environment override. |

Quint bounds the search to eight transitions of a single abstract pass. It does not model arbitrary custom workflow loops, OS races, Git failure details, tool permissions, or multiple resumed passes. An initial stale artifact represents a prior visit rather than a model of checkpoint persistence. Alloy models candidate presence, not model-string syntax, fallback order within a role, or SDK installation. Neither model proves that Rust implements its transitions. The runtime scenarios enter the production engine below preflight and use a local shell double to make outcomes observable and reproducible. They do not prove jcode or Bubblewrap behavior, nor the quality of model advice.
