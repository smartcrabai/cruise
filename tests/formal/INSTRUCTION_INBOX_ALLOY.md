# Instruction inbox Alloy model

Run from the repository root: `bash scripts/check_instruction_inbox_alloy.sh`. It requires Bash, curl, tar, Node.js and either sha256sum or shasum. The runner verifies the Alloy 6.2.0 released distribution jar (SHA-256 `6b8c1cb5bc93bedfc7c61435c4e1ab6e688a242dc702a394628d9a9801edb78d`) and the platform-specific Temurin 25.0.5+8 JDK archive, then extracts the verified JDK into a temporary tools directory. Supported hosts are macOS arm64 and Linux x86_64. A cached download is rehashed before use. The Alloy CLI `help exec`, command listing, Java version, execution output, JSON receipt and witness are retained under `target/formal-reports/instruction-inbox-alloy.*`.

Alloy's `exec` help documents `-c '*'` for selecting all commands and `-o` for a separate output directory. The runner checks the generated receipt rather than relying on the CLI exit status: each named assertion must have `expect 0` and be UNSAT, each witness must have `expect 1` and contain a concrete SAT instance, and no command may be missing or extra.

The model abstracts ledger operations as atomic transitions. It bounds traces to seven states, three ordered IDs and two keys, with unkeyed requests also possible. A lease captures the entire pending snapshot, and arrivals during a lease remain pending. `Carry` represents failed or suspended close, `Completed` expires outstanding items, and crash leaves the lease stranded until reopen. Six assertions cover partition, one lease, closed acceptance, terminal states, deduplication and close/recovery. The witness exercises open, accept, lease, carry, reopen and re-lease of the same pending item.

On 2026-11-07, the runner produced six UNSAT assertions and one SAT witness, and its receipt checker validated all seven results in `target/formal-reports/instruction-inbox-alloy.JaWxKD/`. This is bounded protocol evidence, not an unbounded proof or a demonstration that the Rust implementation refines the model. Filesystem failures, scheduling, actual parallel consumers, fairness and liveness are outside its scope.
