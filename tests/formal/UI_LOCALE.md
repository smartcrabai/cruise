# UI locale executable specifications

These models cover the plan's locale precedence and browser-specific cookie contract. Seven integers/atoms represent supported locales, and zero or absence abstracts absent, `auto`, invalid, and unsupported values. The process selection is environment, saved configuration, system, then English. Each browser uses its own valid cookie or the process locale. The Quint configuration transition abstracts a fresh process resolution after a preference change, not mutation of an already initialized process. Cookie transitions represent separate browser requests. Alloy checks the corresponding static relation and satisfiable cases, including independent browser selections.

These are finite abstractions, not a proof that Rust implements the model. Neither model parses locale strings or cookie sequences, checks warning text or persistence, covers catalog completeness, or proves SSE rendering. Production CLI Gherkin scenarios exercise isolated real child processes, persistent settings, validation, precedence, warnings and translated output. On Windows, isolated child processes clear POSIX locale variables but still detect the operating-system locale; fallback scenarios assert that supported host locale or English, matching the system-then-English model. Browser integration is separately exercised by `tests/webui/language.mjs` through `scripts/check_responsive_webui_bdd.sh`.

Run `bash scripts/check_ui_locale_specs.sh` from the repository root. It creates fresh logs, commands and an independently checked Alloy receipt under `target/formal-reports/ui-locale.*`. The GitHub Actions workflow `.github/workflows/ui-locale-specs.yml` runs the same check on pull requests without secrets, and `scripts/check_formal.sh` also includes it. Setup requires network access or pre-cached verified downloads and supports Darwin arm64 and Linux x86_64.

Pinned tools: Node 26.13.0, Quint 0.33.0 (npm lockfile), Apalache 0.62.1, Alloy 6.2.0 (SHA-256 `6b8c1cb5bc93bedfc7c61435c4e1ab6e688a242dc702a394628d9a9801edb78d`), Temurin JDK 25.0.5+8 LTS, Rust 1.99.1 and Cucumber 0.23.0. JDK archives and checksums are pinned by `scripts/setup_formal.sh`. The runner records Alloy's version and `help exec`, runs every explicitly named Alloy command, and checks SAT witnesses and UNSAT assertions in the JSON receipt.

Quint typechecks and tests the model, simulates with seed 20261023, 1000 samples and five steps, and verifies invariant `safety` with Apalache for five steps. Simulation is not proof. Bounded verification only establishes the invariant within the specified model and bound, not unbounded correctness.
