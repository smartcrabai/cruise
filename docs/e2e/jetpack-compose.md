# Jetpack Compose on Android E2E policy

Applies only to actual Android app UI implemented in Jetpack Compose. Apply the [common UI E2E policy](common.md); do not apply this policy to Android Views, generic mixed/hybrid apps as a whole, or Compose Multiplatform running on a non-Android host.

- **Fast feedback:** Keep assertion-bearing [Compose UI tests](https://developer.android.com/develop/ui/compose/testing) in the repository. When compatible with the project's Compose, Robolectric, Gradle, and Android Gradle Plugin versions, run fast, headless local UI tests with [Robolectric](https://developer.android.com/training/testing/local-tests/robolectric). Robolectric can run Compose UI tests in a simulated Android environment on the host JVM, not on a device or emulator; verify its fidelity is sufficient for each assertion.
- **Preview visuals:** Use [`android preview render`](https://developer.android.com/tools/agents/android-cli/commands/preview_render) to render Compose `@Preview` functions to PNGs without a device or Android Studio, then inspect the image pixels. A host-rendered preview is not the running app and does not replace real-app visual evidence.
- **Live visual evidence:** When suitable existing visual tooling is absent, prefer Android CLI interaction with the actual app on a supported connected Android device or emulator: use [`android input`](https://developer.android.com/tools/agents/android-cli/commands/input) for interaction, save a PNG with [`android screen capture`](https://developer.android.com/tools/agents/android-cli/commands/screen_capture), and inspect its pixels.
- **Persistent runtime assertions:** For saved assertions against the target Android runtime, use instrumented Compose UI tests in the project's `androidTest` source set and give the exact repeatable Gradle task for its module and variant. Do not guess a generic task or treat Robolectric/preview results as instrumented runtime evidence.
- **Optional pixel tests:** Consider [Roborazzi](https://github.com/takahirom/roborazzi) only if pixel-regression assertions are needed and its current setup is compatible with the project's Compose/Robolectric/Gradle stack; it is not required for screenshot inspection or a substitute for target-runtime evidence.
- Use device/emulator evidence for Android system UI, device-specific behavior, or APIs Robolectric does not adequately support. If a required host, runtime, or capability is unavailable, report the exact limitation and do not claim a pass.
