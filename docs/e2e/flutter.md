# Flutter UI policy

Apply the [common UI E2E policy](common.md) to actual Flutter applications and their intended supported targets.

- **Fast feedback:** retain suitable `flutter_test` widget tests. Drive meaningful app UI paths with `testWidgets`, assert consumer-visible results, and save golden images with [`matchesGoldenFile`](https://api.flutter.dev/flutter/flutter_test/matchesGoldenFile.html); update them intentionally with `flutter test --update-goldens`. These tests use Flutter's test environment, so their images and results are fast feedback, not screenshots or runtime evidence from the target app.
- **Optional Impeller check:** Flutter's upstream [`flutter test` command](https://github.com/flutter/flutter/blob/master/packages/flutter_tools/lib/src/commands/test.dart) registers `--enable-impeller`; use `flutter test --enable-impeller` only with an SDK and host/test backend that support it. Record the actual SDK, OS, and renderer; the flag or a test-harness result alone does not establish renderer behavior on the target device. Check [Impeller support](https://docs.flutter.dev/perf/impeller) for the intended target and verify target-specific behavior separately.
- **Persistent E2E:** preserve suitable existing UI tests. If absent, save assertion-bearing [`integration_test`](https://docs.flutter.dev/testing/integration-tests) tests for the real app path, using isolated/reset deterministic data and success plus meaningful failure or boundary assertions. For mobile and desktop, use `flutter test integration_test -d <device-id>`. For a web target, use the documented [Flutter web test flow](https://docs.flutter.dev/testing/integration-tests#test-in-a-web-browser) with `flutter drive` and a compatible ChromeDriver. Record the exact command for the intended target.
- **Visual interaction:** use compatible existing tooling to launch and interact with the actual running target app, save screenshots of meaningful states, and inspect their pixels. The optional [Dart and Flutter MCP server](https://docs.flutter.dev/ai/tools#dart-and-flutter-mcp-server) provides runtime introspection during active debugging; use it for live interaction only when the connected client actually exposes the required actions. Tree/state output is not screenshot or pixel evidence. `integration_test` cannot interact with native platform UI (such as permission dialogs) or platform views; report those and any unexercised plugin/native behavior as limitations rather than claiming coverage.
