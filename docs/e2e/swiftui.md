# SwiftUI and Apple native UI policy

Applies to SwiftUI and other Apple-native iOS or macOS UI targets. Apply the [common UI E2E policy](common.md); do not generalize recommendations to unsupported Apple OS targets.

- **Visual interaction:** use suitable established tooling for the actual app on a representative supported iOS Simulator or macOS runtime, save meaningful screenshots, and inspect their actual pixels. On Xcode 27, Apple’s Xcode agent tools can boot simulators, install and launch apps, synthesize touch events, and capture screenshots; use these only when the host, runtime, permissions, and selected agent integration expose the required tools. For external agents, follow Apple’s [Xcode MCP access documentation](https://developer.apple.com/documentation/xcode/giving-external-agents-access-to-xcode) and check the connected tool capabilities. SwiftUI Preview alone is not visual evidence. ([Xcode 27 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-27-release-notes))
- **Persistent UI E2E:** only when suitable saved UI E2E tooling is absent, store deterministic, assertion-bearing XCTest with XCUIAutomation source and provide the exact repeatable `xcodebuild test` command for the representative supported target runtime.
- **Optional iOS fast loop:** where the app is supported by [simless](https://github.com/abacusai/simless), it requires an Apple Silicon Mac, macOS 15+, Xcode 26+, and an iOS SwiftUI app in an `.xcodeproj` (not an `.xcworkspace`, Tuist project, or pure Swift package app). After `simless init` and `simless up`, it can run headless `simless render <Fixture> --png <dir>`, `simless act <Fixture> tap "#id" type "#field" "text"`, and existing XCUITest tests with `simless test ui`. Simless runs the iOS app in a Mac host, not the iOS Simulator; rendering, pixels, controls, and runtime behavior can differ. Treat it as supplementary fast-loop feedback only, not platform-parity or final E2E evidence; finish with the actual app in the iOS Simulator, saved and pixel-inspected screenshots, and the relevant persistent UI E2E run.
- **Optional simulator optimization:** [simslim](https://github.com/mobai-app/simslim) may reduce simulator resource use on a compatible, isolated macOS host with Xcode and an iOS Simulator runtime. It changes simulator background services and can affect tests that depend on them; it is an optimization, not a runner or prerequisite.
- App Intents Testing may additionally cover actual intent integration; it never replaces UI E2E.
- If the necessary Xcode host, runtime, or selected capability is unavailable, report the precise blocker and complete other reachable work without claiming that capability ran.
