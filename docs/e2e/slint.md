# Slint UI policy

Applies to desktop and embedded apps whose UI is written in Slint (`.slint` files). Apply the [common UI E2E policy](common.md).

- **Visual interaction:** reuse suitable existing visual tooling first; otherwise run the actual Rust app with Slint's [embedded MCP server](https://docs.slint.dev/latest/docs/rust/i_slint_backend_testing/). Set `SLINT_EMIT_DEBUG_INFO=1`, pass `--features slint/mcp` on the command line (never add `mcp` to `Cargo.toml` features), and use a unique `SLINT_MCP_PORT=<port>` for each concurrent app; the server binds to loopback (`127.0.0.1`) by default, so do not set `SLINT_MCP_HOST`. Use the element tree, `@testable` properties, click, drag, and typing tools; save `take_screenshot` output as PNG and inspect its pixels. This preliminary MCP interface is for development automation, not production automation; stop the app when done.
- With no display, set `SLINT_BACKEND=headless-skia` and enable `slint/renderer-skia` at compile time to render the actual app through Skia's software rasterizer. Plain `SLINT_BACKEND=headless` uses Skia's software rasterizer when `slint/renderer-skia` is enabled, otherwise Slint's built-in software renderer; `headless-skia` and `headless-software` force a renderer choice ([backend and renderer details](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backends_and_renderers)). Headless rendering is windowless and software-rasterized: screenshots do not evidence platform window chrome, GPU/compositor behavior, or platform-specific rendering; use the target runtime when those matter and report gaps. This unstable backend selection is for automation only, not production code.
- **Persistent E2E:** only when suitable saved UI tests are absent, use Rust integration tests with `i-slint-backend-testing` as a dev-dependency pinned with `=x.y.z` to exactly the app's `slint` version (it does not follow semver). Initialize with `init_integration_test_with_system_time()` or `init_integration_test_with_mock_time()`, locate elements with `ElementHandle::find_by_accessible_label` or `find_by_element_id`, drive them with `single_click` or accessible actions, and assert application state. Advance animations and timers with `mock_elapsed_time()`, not sleeps.
- The testing backend is separate from the headless app backend: it simulates a window system but renders no pixels and measures text at a fixed size, so its tests are not visual evidence; pair them with actual-app MCP screenshots when available. The API is preliminary and Rust-only; for Slint apps in other languages, reuse existing tooling and report missing capability.
